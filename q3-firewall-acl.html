Question 3 of N — Configure Firewall Access Control List

A security engineer is configuring a stateless packet-filtering firewall that sits between the Internet, a DMZ (containing a public web server), and the internal LAN. Rules are evaluated top-down; first match wins. An implicit deny all exists at the bottom.

Security Policy Requirements
  • Host 10.0.1.77 has been flagged as compromised — block all its outbound traffic.
  • Block Telnet (TCP 23) from any source to any destination.
  • Allow inbound HTTPS (TCP 443) from the Internet to the DMZ web server 203.0.113.10.
  • Allow the internal LAN 10.0.1.0/24 to query external DNS (UDP 53).
  • Allow the internal LAN 10.0.1.0/24 to browse the web (TCP 80 and 443) outbound.
  • Block everything else — no implicit trust.

Drag the ACL rules into the correct top-to-bottom order so the policy is enforced properly. Ordering mistakes can create security gaps or block legitimate traffic.

Drag cards up or down to reorder. Mobile: touch-drag supported.
Answer Key & Explanation
Why rule order matters in stateless ACLs:
A stateless firewall has no session state — every packet is matched independently from the top. The first rule that matches is applied; subsequent rules are ignored. This means a broad PERMIT placed above a specific DENY will silently nullify that deny. Classic mistakes: (1) putting the implicit deny-all in the middle, (2) letting a compromised host match a subnet PERMIT before it hits its specific DENY, (3) blocking Telnet after a broad permit that already covers TCP traffic.

Correct order rationale:
Rule 1 — deny 10.0.1.77 first, before the LAN subnet permit, or the compromised host gets web access.
Rule 2 — deny Telnet globally before any broad permits create accidental exceptions.
Rules 3-5 — specific permits (inbound HTTPS, DNS, LAN web); ordering among them is flexible here.
Rule 6 — implicit deny all must be last; placing it earlier would block legitimate traffic below it.
